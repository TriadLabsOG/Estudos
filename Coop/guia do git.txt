Aqui está um roteiro de 10 exercícios práticos simulando o dia a dia de uma equipe (você e o Lucas).

Como usar este roteiro:
Decidam quem é quem: Um será o "Dev A" e o outro o "Dev B" em cada exercício. Revezem esses papéis.

Regra de Ouro: Sigam o fluxo git pull -> (codar) -> git add -> git commit -> git push.

Exercício 1: O "Olá Mundo" da Colaboração
Objetivo: Garantir que ambos conseguem enviar código para o mesmo repositório sem erros básicos.

Dev A: Cria um arquivo saudacao.py. Escreve um código que pergunta o nome do usuário e imprime "Olá, [Nome]!". Faz o commit e push.

Dev B: Dá git pull. Abre o arquivo e adiciona uma linha extra perguntando "Como você está hoje?". Faz o commit e push.

Dev A: Dá git pull para ver a atualização.

Exercício 2: Calculadora de IMC (Simples)
Objetivo: Trabalhar no mesmo arquivo sem conflito (edição sequencial).

Dev A: Cria imc.py. Faz a parte que pede o Peso e a Altura do usuário (float). Comita e Push.

Dev B: Dá git pull. Adiciona o cálculo: imc = peso / (altura ** 2). Imprime o valor do IMC na tela. Comita e Push.

Dev A: Dá git pull. Adiciona as condições (if imc < 18.5: print("Abaixo do peso"), etc.). Comita e Push.

Exercício 3: Jokenpô (Pedra, Papel, Tesoura) - Ramificação
Objetivo: Usar branches para não atrapalhar a main.

Dev A: Na main, cria o arquivo jokenpo.py e importa a biblioteca random. Comita e Push.

Dev B: Cria uma branch chamada logica-computador. Escreve o código para o computador escolher aleatoriamente entre pedra, papel e tesoura. Comita e Push essa branch.

Dev A: Cria uma branch chamada interface-usuario. Escreve o código que pede a opção do jogador e valida se é válida. Comita e Push essa branch.

Juntos: Façam o Merge das duas branches na main (pode ser via Pull Request no site ou no terminal).

Exercício 4: O Conflito Forçado (Para perder o medo)
Objetivo: Aprender a resolver conflito de edição na mesma linha.

Dev A: Cria um arquivo configuracoes.py com uma variável: versao = "1.0". Comita e Push.

Dev B: Dá git pull.

AGORA AO MESMO TEMPO:

Dev A: Muda a versão para versao = "1.1-alpha" e salva.

Dev B: Muda a versão para versao = "2.0-beta" e salva.

Ação: Ambos tentam fazer commit e push. O segundo a enviar vai ter o push rejeitado.

Resolução: Quem foi rejeitado deve dar git pull, resolver o conflito no código (escolhendo qual versão fica ou criando uma 1.5), commitar e dar push novamente.

Exercício 5: Empréstimo Bancário (Aula 12)
Objetivo: Complementar a lógica do outro.

Dev A: Cria emprestimo.py. Pede o valor da casa, salário e em quantos anos vai pagar. Push.

Dev B: Pull. Calcula o valor da prestação mensal. Push.

Dev A: Pull. Adiciona a condição: Se a prestação for maior que 30% do salário, nega o empréstimo, senão aprova. Push.

Exercício 6: Adivinhação de Número (Refatoração)
Objetivo: Melhorar o código de um colega.

Dev B: Cria adivinha.py. Faz o computador "pensar" num número de 0 a 5 e pede pro usuário tentar adivinhar. Faz um if/else simples (Acertou/Errou). Push.

Dev A: Pull. Modifica o código para dar mensagens mais divertidas (ex: "Errou feio!" ou "Miserável, acertou!"). Push.

Exercício 7: Comparador de Números (Pastas Diferentes)
Objetivo: Trabalhar em paralelo sem conflitos.

Dev A: Cria a pasta matematica e dentro dela o arquivo maior_menor.py. Faz um script que lê dois números e diz qual é o maior.

Dev B: Cria a pasta analise e dentro dela o arquivo par_impar.py. Faz um script que lê um número e diz se é par ou ímpar.

Juntos: Façam Push. Vejam que o Git aceita os dois sem reclamar.

Exercício 8: Alistamento Militar
Objetivo: Trabalhar com datas (import datetime).

Dev A: Cria alistamento.py. Importa date de datetime e pega o ano atual. Pede o ano de nascimento. Push.

Dev B: Pull. Calcula a idade. Faz a lógica: se tiver 18, hora de alistar; se for menor, diz quanto tempo falta; se for maior, diz quanto tempo passou. Push.

Exercício 9: Gerenciador de Pagamentos (Desafio Aula 12)
Objetivo: Construção complexa em etapas.

Dev A: Cria loja.py. Pede o preço das compras e mostra o menu de opções de pagamento (1. À vista dinheiro, 2. À vista cartão, 3. 2x cartão, 4. 3x ou mais). Push.

Dev B: Pull. Implementa as opções 1 e 2 (com descontos). Push.

Dev A: Pull. Implementa a opção 3 (preço normal). Push.

Dev B: Pull. Implementa a opção 4 (juros de 20%). Push.

Exercício 10: O "Hotfix" (Correção Urgente)
Objetivo: Simular um erro em produção.

Dev A: Pega o exercício anterior (loja.py) e muda o juros da opção 4 para 500% (simulando um erro de digitação). Comita e Push com a mensagem "Ajuste final".

Dev B: Percebe o "erro" (simulação). Cria uma branch chamada hotfix-juros. Corrige para 20%. Comita e Push a branch.

Dev A: Aprova a alteração do Dev B e faz o Merge para a main.

Dica: Para esses exercícios ficarem divertidos, tentem usar o VS Code com a extensão Live Share em alguns momentos para programarem juntos em tempo real, mas usem o Git para salvar as versões finais! Bom treino!
